## 1. Обзор

### 1.1 Цель

Разработать AI Operating System (osaI) на базе форка OpenClaw — open-source personal AI assistant (100k+ GitHub stars, MIT license). osaI расширяет OpenClaw от персонального ассистента до полноценного AI-слоя управления системой: файлы, браузер, shell, API, приложения, мессенджеры, desktop-интеграция.

### 1.2 Контекст

OpenClaw — реальный, активно развивающийся проект (запуск ноябрь 2025, 100k+ звёзд, 500+ контрибьюторов, спонсорство OpenAI и Vercel). Он уже решает 80% задач персонального AI-ассистента. Вместо reimplement с нуля, мы форкаем OpenClaw и расширяем его до AI OS.

### 1.3 Что наследуется от OpenClaw

| Компонент | Описание |
|-----------|----------|
| Gateway | WebSocket control plane (ws://127.0.0.1:18789) |
| Pi Agent Runtime | RPC-режим с tool streaming + block streaming |
| Skills System | SKILL.md формат, bundled/managed/workspace skills |
| Session Model | Main session + изолированные group sessions |
| Activation Modes | always, mention, wake word, passive |
| Docker Sandboxing | Контейнеры для non-main сессий |
| Model Failover | Цепочка провайдеров, auth profile rotation |
| Canvas / A2UI | Agent-driven визуальное рабочее пространство |
| Device Nodes | macOS/iOS/Android pairing через WS |
| Voice | Wake word + Talk Mode (ElevenLabs + system TTS) |
| ClawHub | Registry для managed skills |
| Config | openclaw.json конфигурация |

### 1.4 Что добавляет osaI

| Компонент | Описание |
|-----------|----------|
| Deep Memory | Долгосрочная структурированная память (SQLite + Qdrant) с RAG |
| Knowledge Base | Ингест документов, семантический поиск по личной базе знаний |
| OS Integration | System tray, desktop notifications, file watchers, process management |
| Observability | OpenTelemetry: traces, metrics, audit log, dashboard |
| Multi-platform | Нативная поддержка Linux + Windows |
| Z.ai Provider | Дополнительный облачный LLM провайдер |

### 1.5 Ключевые принципы

| Принцип | Описание | Источник |
|---------|----------|----------|

## 3. Ядро агента (Agent Core)

### 3.1 Agent Loop

osaI использует agent loop OpenClaw без изменений:

```
INTAKE → CONTEXT ASSEMBLY → MODEL INFERENCE → TOOL EXECUTION → STREAMING → PERSISTENCE
    ↑                                                              │
    └────────────────────── tool_use loop (при необходимости) ──────┘
```

### 3.2 Hook Points

| Hook | Источник | Описание |
|------|----------|----------|
| `before_model_resolve` | OpenClaw | Выбор модели, rotation auth profiles |
| `before_prompt_build` | OpenClaw | Модификация промпта, инъекция RAG-контекста |
| `before_agent_start` | OpenClaw | Инициализация перед запуском агента |
| `before_tool_call` | OpenClaw | Permission check, sandbox verify |
| `after_tool_call` | OpenClaw | Result processing, metrics, memory store |
| `agent_end` | OpenClaw | Post-processing, notifications |
| `on_error` | OpenClaw | Error handling, fallback logic |
| `before_memory_query` | **osaI** | RAG search перед context assembly |
| `after_memory_extract` | **osaI** | Post-processing extracted facts |
| `on_file_access` | **osaI** | Audit + sandbox check для файловых операций |
| `on_desktop_notification` | **osaI** | System tray notification dispatch |

### 3.3 Session Model

Наследуется от OpenClaw:

- **Main Session** — persistent, прямая сессия с пользователем, полная история, все tools
- **Group Sessions** — изолированные сессии для групп/контекстов
- **Activation Modes**: always, mention, wake word, passive
- **Queue Modes**: sequential, parallel
- **Persistence**: SQLite, serialization/deserialization, pruning при overflow

### 3.4 Model Failover

Цепочка провайдеров с auto-rotation:

```
Request → Anthropic Claude (primary)
              │
              ├─ 200 OK → response
              ├─ 429 Rate Limit → wait + retry
              ├─ 500 Error → OpenAI GPT (fallback)
              │                  ├─ OK → response
              │                  └─ Error → Z.ai (fallback)
              │                              ├─ OK → response
              │                              └─ Error → Ollama (local)
              └─ Timeout → Ollama (local)
                           └─ response
```

**Auth Profile Rotation**: несколько API-ключей для одного провайдера, автоматическая ротация при rate limit.

**Circuit Breaker**: при N последовательных ошибках провайдера — переключение на следующего в цепочке.

- **Returns**: описание результата

### 4.3 Bundled Skills (MVP)

#### 4.3.1 Filesystem Skill

**Операции:**

| Операция | Параметры | Категория | Confirmation |

| `read_file` | `{path, offset?, limit?}` | Read | Auto |

**Безопасность:**
- Список заблокированных команд (hardcoded + конфигурируемый)

### 5.2 Session Memory (OpenClaw)

Наследуется от OpenClaw — хранение в SQLite:
- Session messages с историей

- Session state (serialization/deserialization)

### 5.3 Long-term Memory (osaI)

```typescript
interface MemoryEntry {
  id: string;
  content: string;
  embedding: number[];       // 1536-dim (OpenAI) или 384-dim (local MiniLM)
  category: MemoryCategory;
  tags: string[];
  sourceSession: string;
  accessCount: number;
  createdAt: Date;
  metadata: Record<string, any>;
}

enum MemoryCategory {
  FACT,           // извлечённые факты из диалогов
  PREFERENCE,     // предпочтения пользователя
  KNOWLEDGE,      // знания о проектах/доменах
  ERROR,          // ошибки и решения
  PATTERN,        // изученные паттерны поведения
}
```

**SQLite tables:**
```sql
CREATE TABLE memory_entries (
  id TEXT PRIMARY KEY,
  content TEXT NOT NULL,
  embedding_id TEXT,
  category TEXT NOT NULL,
  tags TEXT,                -- JSON array
  source_session TEXT,
  access_count INTEGER DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  metadata TEXT             -- JSON
);

CREATE TABLE knowledge_documents (
  id TEXT PRIMARY KEY,
  title TEXT,
  path TEXT,
  chunks_count INTEGER DEFAULT 0,
  tags TEXT,                -- JSON array
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE knowledge_chunks (
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL REFERENCES knowledge_documents(id),
  content TEXT NOT NULL,
  embedding_id TEXT,
  chunk_index INTEGER NOT NULL
);
```

### 5.4 RAG Pipeline

Интеграция через hook `before_prompt_build`:

```
1. User message received
       │
       ▼
2. before_prompt_build hook
       │
       ▼
3. Memory query (semantic search via Qdrant)
   ├─ Query: user message embedding
   ├─ Top-k=5, similarity > 0.7
   └─ Returns: relevant memories + knowledge chunks
       │
       ▼
4. Inject into system prompt:
   ## Relevant Memory
   - [fact] User prefers dark theme
   - [knowledge] Working on project "osaI"
   - [error] Qdrant timeout → fixed by restart
       │
       ▼
5. Model inference with enriched context
       │
       ▼
6. after_tool_call → extract facts from response
       │
       ▼
7. Store new facts in long-term memory
```

### 5.5 Knowledge Base

- **Ingest**: документ → chunking (1024 tokens, overlap 128) → embedding → Qdrant + SQLite
- **Query**: query → embedding → vector similarity search → rerank → return passages with sources
- **Sources**: add, remove, list по тегам

### 5.6 Embedding Model

| Провайдер | Модель | Размерность | Когда используется |
|-----------|--------|------------|-------------------|

## 8. Безопасность (Guardrails)

### 8.1 Многоуровневая модель

```
Layer 1: Network (OpenClaw)
├─ WS на localhost (127.0.0.1:18789)
├─ Tailscale для remote access (E2E encryption)
└─ Device pairing verification

Layer 2: Sandbox (OpenClaw)
├─ Docker containers для non-main сессий
├─ Allowlist/denylist для tools
└─ Resource limits (CPU, memory, network)

Layer 3: Permission Prompts (OpenClaw + osaI)
├─ before_tool_call → permission check
├─ Category-based: read=auto, write=confirm, exec=confirm
└─ Desktop notification для permission requests

Layer 4: File Sandbox (osaI)
├─ Allowed dirs: ~/projects, ~/documents, /tmp/osai
├─ Blocked patterns: ~/.ssh/**, ~/.gnupg/**, /etc/**
├─ Symlink resolution
└─ on_file_access hook → audit logging

Layer 5: Shell Security (OpenClaw + osaI)
├─ Blocked commands list
├─ Timeout enforcement (120s)
├─ Command logging
└─ Dangerous pattern detection

Layer 6: Audit (osaI)
├─ All actions logged with trace_id
├─ Permission decisions recorded
└─ Queryable via API
```

## 16. Workspace (AGENTS.md, SOUL.md)

### AGENTS.md

```markdown
# osaI Agent

You are osaI, an AI Operating System agent. You execute user intents by using tools and skills.

## Capabilities
- File system management (read, write, search, move, delete)
- Shell command execution (with safety checks)
- Browser automation (navigate, click, fill, screenshot)
- HTTP/API integration
- Desktop OS integration (notifications, processes, file watchers)
- Long-term memory and knowledge base management
- Multi-channel communication (Telegram, WhatsApp, Discord, Slack, CLI)

## Rules
- Always confirm before destructive operations (write, delete, execute)
- Stay within sandbox boundaries
- Log all actions for audit
- Ask for clarification when intent is ambiguous
- Remember important facts across sessions
- Use memory and knowledge base to provide better responses
```

### SOUL.md

```markdown
# osaI Soul

## Values
- **Helpfulness**: Execute user intents efficiently and completely
- **Honesty**: Report errors and limitations transparently
- **Safety**: Never bypass sandbox or permission checks
- **Privacy**: Keep user data local, never send to third parties
- **Clarity**: Explain what you're doing and why

## Tone
- Concise and direct
- Show progress for multi-step tasks
- Proactively confirm dangerous operations
```

## 18. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| OpenClaw upstream breaking changes | Средняя | Высокое | Pin version; отдельный fork; abstraction layer над upstream |
| LLM API downtime | Средняя | Высокое | 4-звенная failover цепочка; auth rotation; circuit breaker |
| Агент выполняет разрушительное действие | Средняя | Критичное | 6-layer security; Docker sandbox + confirmation + audit |
| Контекстное окно переполнено | Высокая | Среднее | Auto-pruning + summarization; RAG вместо полного контекста |
| Высокая стоимость LLM API | Средняя | Среднее | Token tracking + cost metrics; Ollama fallback |
| Qdrant embedded на Windows | Средняя | Среднее | Fallback на sqlite-vec; интерфейс через абстракцию |
| Node.js native modules на Windows | Средняя | Среднее | Тестировать на Windows CI; использовать pure JS где возможно |
| Solo developer overload | Высокая | Высокое | Форк вместо написания с нуля; leverage OpenClaw community |
| Sandbox обход | Низкая | Критичное | Docker isolation; symlink resolution; blocked patterns |
| Кроссплатформенность (Linux/Windows) | Средняя | Среднее | CI на обеих платформах; chokidar/node-notifier поддерживают обе |

## 19. Компромиссы (Tradeoffs)

### 19.1 Принятые решения

| Решение | Альтернатива | Обоснование |
|---------|-------------|-------------|
| TypeScript/Node.js (не Rust) | Rust — выше производительность | OpenClaw на TS; 80% кода готово; npm ecosystem; кроссплатформенность |
| Fork OpenClaw (не с нуля) | Custom implementation | Готовый gateway, agent, 20+ channels, skills; экономия месяцев |
| SQLite + Qdrant (не Pinecone) | Pinecone — cloud | Local-first; Qdrant embedded; SQLite для structured data |
| SvelteKit (не Next.js) | Next.js — больше ecosystem | Легче, быстрее; desktop dashboard не нужен SSR |
| pino (не winston) | Winston — больше formatters | 6x быстрее; structured JSON |
| Docker sandbox (не firecracker) | firecracker — безопаснее | OpenClaw использует Docker; sufficient isolation |
| Nативная Windows (не только WSL) | Только WSL | Расширение аудитории; node.js кроссплатформенный |
| Z.ai в цепочке | Только Claude + GPT + Ollama | Ещё одна fallback-опция для облачных провайдеров |

### 19.2 Балансы

- **Скорость разработки vs контроль**: В пользу скорости — форк даёт 80% кода, но зависимость от upstream
- **Функциональность vs стабильность**: MVP на стабильном fork; osaI extensions в отдельных пакетах
- **Безопасность vs UX**: Docker + confirmation для write/exec; read — auto в sandbox
- **Стоимость API vs качество**: Claude primary, GPT/Z.ai fallback, Ollama offline
- **Кроссплатформенность vs сложность**: Нативная Windows + Linux, но через проверенные библиотеки
