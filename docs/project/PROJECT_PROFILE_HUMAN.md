# Резюме понимания проекта

## Как мы поняли ваш запрос

Вы предоставили подробную спецификацию (ТЗ) проекта **osaI v3** -- AI Operating System, которая строится на базе форка существующего open-source проекта **OpenClaw** (персональный AI-ассистент с 100k+ звёзд на GitHub). Цель osaI -- расширить OpenClaw от простого чат-ассистента до полноценного AI-слоя управления операционной системой: файлы, браузер, командная строка, API, приложения, мессенджеры, рабочие стол.

Разработка ведётся в ветке **OSAI-DEV-V3**. Артефакты проекта генерируются на основе спецификации версии 3.0 от 2026-03-28.

## Тип и направление проекта

**Тип:** Форк и расширение существующей системы (не разработка с нуля)

**Направление:** Системное программирование + AI/ML интеграция

**Ключевая идея:** Вместо того чтобы писать всё с нуля, проект берёт за основу готовую систему OpenClaw (которая уже решает ~80% задач) и добавляет критически важные расширения:

- Управление несколькими чатами одновременно (до 20)
- Глубокая память с семантическим поиском (RAG)
- Интеграция с Telegram на уровне бота + пользовательского аккаунта
- Локальный голосовой стек (распознавание и синтез речи)
- Глубокая интеграция с операционной системой (системный трей, уведомления, мониторинг)
- Наблюдаемость (трассировка, метрики, аудит)

## Что входит в объём работ

### MVP (первая версия -- то, что делается в первую очередь)

- **Ядро системы**: WebSocket-шлюз для управления, агентский цикл (получение запроса -> сбор контекста -> вызов модели -> выполнение инструментов -> отправка ответа), система перехватчиков (hooks)
- **Система навыков (skills)**: Работа с файлами и командной строкой с sandbox-изоляцией и запросами подтверждения на опасные операции
- **Мультичаты**: До 20 независимых чатов, каждый со своей историей, но с общей долговременной памятью
- **Память**: Трёхуровневая система -- память чата, память сессии, долговременная структурированная память с векторным поиском (RAG)
- **База знаний**: Загрузка документов, разбиение на фрагменты, семантический поиск
- **Telegram**: Бот + пользовательский аккаунт (userbot) + двусторонняя синхронизация сообщений (mirror)
- **LLM-провайдеры**: Z.ai (основной), Yandex (запасной + голос), Anthropic Claude (запасной), OpenAI GPT (запасной), Ollama (локальный, оффлайн)
- **ОС-интеграция**: Системные уведомления, информация о системе
- **CLI**: Интерфейс командной строки с псевдографическим интерфейсом (TUI)
- **Безопасность**: 7-уровневая модель защиты (сеть, песочница, разрешения, файловый песок, безопасность команд, безопасность Telegram, аудит)
- **Тестирование**: Модульные, интеграционные и сквозные (E2E) тесты

### V1 (вторая волна)

- Голосовой стек (локальное распознавание и синтез речи через Ollama, облачный фолбэк через Яндекс)
- Системный трей и мониторинг файловой системы
- Наблюдаемость (OpenTelemetry: трассировки, метрики, Prometheus, журнал аудита)
- Веб-панель управления (SvelteKit)
- Дополнительные мессенджеры: WhatsApp, Discord, Slack
- Демон для Windows (Windows Service)

### V2 (третья волна -- перспективы)

- Мультиагентная архитектура
- Маркетплейс плагинов
- Совместная работа команд
- Продвинутый RAG (переранжирование, гибридный поиск)
- Приложение для рабочего стола (Electron/Tauri)

## Ключевые приоритеты

1. **Безопасность** (критический приоритет) -- 7 уровней защиты: от сетевой изоляции до полного аудита всех действий. Агент не может выполнить разрушительное действие без подтверждения пользователя.

2. **Надёжность** (высокий приоритет) -- 5-уровневая цепочка запасных LLM-провайдеров с автоматическим переключением при ошибках. Локальный Ollama как фолбэк для работы оффлайн.

3. **Независимость от облака** (локальность) -- Все данные хранятся на машине пользователя. Нет облачного бэкенда, нет пользовательских аккаунтов, нет подписок.

4. **Масштабируемость разработки** (сохраняемая) -- 80% кода наследуется от OpenClaw, что позволяет одному разработчику создавать полноценную AI OS.

5. **Кроссплатформенность** -- Нативная поддержка Linux и Windows (не только через WSL).

## Ограничения и допущения

### Ограничения

- Один пользователь на установку (нет многопользовательского режима)
- Нет мобильных нативных приложений (мессенджеры -- основной мобильный канал)
- Нет облачного хостинга (только локальная установка)
- Нет подписок и биллинга (open-source проект)
- Зависимость от upstream-проекта OpenClaw (возможны breaking changes)
- Telethon userbot несёт риск блокировки со стороны Telegram
- Один разработчик на проекте (ограничение по скорости разработки)

### Допущения

- Репозиторий OpenClaw доступен для форка
- Z.ai предоставляет совместимый с OpenAI API
- Yandex Foundation Models API доступен и включает текст, эмбеддинги, распознавание и синтез речи
- На целевых машинах установлен Docker (для песочницы) и Ollama (для локальных моделей)
- Node.js 22.16+ обеспечивает достаточную производительность

## Риски и компромиссы

### Основные риски

| Риск | Как решается |
|------|-------------|
| OpenClaw изменит API и сломает совместимость | Фиксация версии, отдельный форк, абстракция над upstream |
| LLM-провайдеры будут недоступны | 5-уровневая цепочка фолбэка, автоматический circuit breaker |
| Агент выполнит разрушительное действие | 7-уровневая безопасность: песочница Docker, подтверждения, аудит |
| Telethon userbot будет заблокирован Telegram | Rate limiting, легитимное использование, фолбэк на режим только бота |
| Один разработчик не справится с объёмом | Форк вместо написания с нуля (80% кода готово), leverage сообщества OpenClaw |
| Qdrant не будет работать на Windows | Фолбэк на sqlite-vec |
| Переполнение контекстного окна | Автоматическая обрезка + суммаризация, RAG вместо полного контекста |

### Принятые компромиссы

- **Скорость разработки важнее полного контроля** -- форк OpenClaw даёт быстрый старт, но создаёт зависимость от upstream
- **Безопасность важнее удобства** -- каждое действие записи/удаления/выполнения требует подтверждения
- **Стоимость API важнее идеального качества** -- основной провайдер Z.ai, облачные фолбэки, локальный Ollama бесплатно
- **Кроссплатформенность важнее простоты** -- нативная поддержка Windows добавляет сложности, но расширяет аудиторию
- **Voice local-first важнее идеального качества** -- Ollama для голоса по умолчанию (среднее качество), Яндекс для лучшего качества
